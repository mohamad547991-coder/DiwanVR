# DiwanVR — محاكاة أعمال الديوان على Quest

مشروع Unity للتدرب على التعامل مع الأوراق والمصنفات والطابعة والختم داخل مكتب افتراضي، مع تتبع اليدين ووحدات التحكم. الإصدار الحالي للكود: **0.4.4**، وAndroid versionCode: **8**.

## حالة التحقق

بتاريخ 2026-11-10 نجحت ترجمة ملفات C# بفاحص Roslyn باستخدام مراجع Unity المثبتة، ونجح 18 اختبارًا لمنطق القرص بالأصابع و13 اختبار Python للتحقق من أدلة الإصدار. هذه ليست تجربة تشغيل داخل Unity أو داخل النظارة.

تعذّر تشغيل اختبارات Unity الجديدة من بيئة التنفيذ بسبب فشل تهيئة الترخيص. **لم يُبنَ APK للإصدار 0.4.4 ولم تُختبر هذه التعديلات على Quest 3S بعد.** لا تتضمن ملفات المصدر APK قديمًا باسم الإصدار الجديد. تمر اختبارات GitHub Actions على أدوات التحقق فقط؛ لا تعني نجاح التشغيل على النظارة.

## التشغيل والبناء

المتطلبات: Unity **6000.6.4f1** مع Android Build Support وSDK/NDK/OpenJDK، وPython **3.11+**. افتح مجلد `UnityProject` من Unity Hub، وانتظر استيراد الحزم ثم افتح `Assets/Diwan/Scenes/Diwan.unity`.

قبل البناء، أغلق محرر المشروع وشغّل `Prepare_Quest_0.4.4.cmd`. ينفذ الاختبارات ثم يبني APK فقط بعد نجاحها. يمكن تشغيل الخطوتين منفصلتين:

```powershell
& ".\Test_Unity_0.4.4.ps1" -Batch
& ".\Build_Quest_0.4.4.ps1"
```

تقبل الأداتان `-UnityExecutable` إذا كان Unity مثبتًا في مكان آخر. لا تستخدم `-nographics` لأن الاختبارات تتحقق من الصورة المرسومة. يفضّل المشغّل PowerShell 7 (`pwsh`) عند توفره؛ Windows PowerShell 5.1 رفض تشغيل السكربت من بيئة التنفيذ الحالية، ولم تُغيَّر سياسة التنفيذ.

المخرجات الناجحة: `Install/DiwanVR_0.4.4_Quest.apk` وإيصال بناء مطابق. تُحفظ سجلات الاختبار في `TestLogs` وتقارير كل تشغيل في `UnityProject/Validation/run-*`. يتوقف الإجراء عند أي فشل، ويتحقق من توقيع APK ومعمارية ARM64 والهوية والإصدار والبصمة.

داخل Unity يمكن اختيار `Diwan VR > 0.4.4 - Test scene and interactions`. الفحص يجرب المشهد والتفاعلات وصورة الكاميرا ومحرّك الرسم الخاص بالجودة المحمولة. فحص الصورة يكشف الإطار الفارغ أو المسيطر عليه لون واحد، ولا يثبت صحة كل عنصر أو النص أو الرؤية المجسّمة.

## الإصلاحات

- تثبيت تعطيل Optimize Buffer Discards في إعدادات Android وMeta Quest، مع منع البناء إذا عادت الإعدادات غير المتوافقة. هذه معالجة لمشكلة موثقة مشابهة لاختفاء العناصر المعتمة، ويظل اختبار الجهاز ضروريًا: [تحقيق Meta](https://developers.meta.com/vr/support/investigations/2983595051984902/).
- الحفاظ على التظليل، ومنع حذف تنويعات Shader التجريبية في إصدار Quest.
- وضع المستخدم داخل نقطة البداية مع تصحيح إزاحة التتبع، وحماية الإمساك من فقدان تتبع الأصابع.
- تحرير مجسّمات الورق التي تُنشأ عند النسخ والتثقيب، دون حذف مجسّمات الأصول.
- التقاط صورة اختبار مستقلة بعد رسم الكاميرا، واعتبار الصورة الفارغة فشلًا.
- عدم تجاهل أخطاء XR الفعلية أو السكربتات المفقودة ضمن أخطاء المحرر المتوقعة.
- فصل مهلة اختبار الختم عن مهلة الطابعة، وتحديد مهلة انتظار المحرر والبناء.
- ربط نجاح الاختبارات ببصمة الكود والمشهد، وربط إيصال البناء ببايتات APK ونتائج الاختبارات الخاصة بالتشغيل نفسه.

## الاختبارات المستقلة

```powershell
python -m unittest discover -s Tests -p "test_*.py" -v
python Tests/run_pinch_test.py
python check_source.py
```

فاحص C# الأخير يحتاج استيراد المشروع أولًا لإنشاء `Library/ScriptAssemblies`. لا يغني عن اختبارات Unity.

## تجربة Quest 3S

بعد بناء 0.4.4، ثبّت APK الجديد وتحقق من ظهور المكتب والأرضية والطاولة والخزائن في العينين. جرّب تحريك الرأس، اليدين ووحدات التحكم، الإمساك والتحرير، نسخ الورق وثقبه وختمه وإدخاله في المصنف. إذا استمر البياض فاحتفظ بسجل الجهاز وإصدار نظام Quest؛ فحص المحرر وحده لا يشخّص برنامج تشغيل النظارة.
